模範回答

```sql
UPDATE actors
SET first_name ='hisaju', last_name='kikumoto'

```

値は取得できるが、不正解となる。

その理由は `""` を使っているか `''` を使っているかの違い。

SQLの標準規格（ANSI SQL）では、**文字列リテラルはシングルクォーテーション（'）で囲む** と定められているとのこと。

`""` を使うと、MySQL では動作するが、他の SQL では動作しない可能性があるとのこと。

**IS NULL と IS NOT NULL**

自分のためのメモ

null のカラムを取得するときは、 `IS NULL` を使う。

指定のカラムが NULL の指定。

```sql
SELECT *
  FROM テーブル名
WHERE カラム名 IS NULL
```

指定のカラムが NULL でない指定

```sql
SELECT *
  FROM テーブル名
WHERE カラム名 IS NOT NULL

```

**昇順と降順がごちゃごちゃになる**

覚え方。

昇順は、小さいのが上。

降順は、大きいのが上。

昇順は、小さい値から大きい値へ「上がる」

降順は、大きい値から小さい値へ「下がる」

英語

降順　**Descending order** 

昇順　**Ascending order**

SQL

降順　DESC

昇順　ASC

自分の回答

```sql
SELECT categories.name, COUNT(films.id) AS number_of_film
FROM categories
JOIN film_categories
ON categories.id = film_categories.category_id
JOIN films
ON film_categories.film_id = films.id
GROUP BY categories.name
HAVING number_of_film > 3;
```

模範回答

```sql
SELECT categories.name, count(*) AS number_of_film
FROM categories
INNER JOIN film_categories ON film_categories.category_id = categories.id
GROUP BY categories.id, categories.name
HAVING (number_of_film >= 3)
ORDER BY number_of_film desc
```

**改善点**

GROUP BY句での集約キーの選択

自分の回答では `GROUP BY categories.name` と記述した。

でも、name カラムは一意制約がないので、同姓同名の人物がいると集約されてしまう。

なので、一意制約がないカラムを集計するときは、 id も一緒に集計する。

模範回答 `GROUP BY categories.id, categories.name`

**内部結合と外部結合**

内部結合は「どちらかのテーブルに存在しない場合は結合結果から消滅される」

`JOIN` はデフォルトで `INNER JOIN` として扱われる。

外部結合は種類がある。

`LEFT JOIN` は、左側のテーブルをすべて表示する。

例

**usersテーブル**

| **id** | **name** |
| --- | --- |
| 1 | taro |
| 2 | jiro |
| 3 | hanako |
| 4 | saito |

**postsテーブル**

| **id** | **body** | **user_id** |
| --- | --- | --- |
| 1 | Hello | 3 |
| 2 | Hi | 1 |
| 3 | Good | 2 |

```sql
SELECT *
  FROM users
  LEFT JOIN posts
    ON users.id = posts.user_id
```

+------+--------+------+-------+---------+
| id   | name   | id   | body  | user_id |
+------+--------+------+-------+---------+
|    3 | hanako |    1 | Hello |       3 |
|    1 | taro   |    2 | Hi    |       1 |
|    2 | jiro   |    3 | Good  |       2 |
|    4 | saito  | NULL | NULL  |    NULL | ← NULLになる❗️ 
+------+--------+------+-------+---------+

`RIGHT JOIN` は右のテーブルを全て表示する。

**usersテーブル**

| **id** | **name** |
| --- | --- |
| 1 | taro |
| 2 | jiro |
| 3 | hanako |

**postsテーブル**

| **id** | **body** | **user_id** |
| --- | --- | --- |
| 1 | Hello | 3 |
| 2 | Hi | 1 |
| 3 | Good | 2 |
| 4 | Sorry | 4 |

```sql
SELECT *
  FROM users
  RIGHT JOIN posts
    ON users.id = posts.user_id
```

+------+--------+------+-------+---------+
| id   | name   | id   | body  | user_id |
+------+--------+------+-------+---------+
|    1 | taro   |    2 | Hi    |       1 |
|    2 | jiro   |    3 | Good  |       2 |
|    3 | hanako |    1 | Hello |       3 |
| NULL | NULL   |    4 | Sorry |       4 |　← name が NULLに❗️
+------+--------+------+-------+---------+

if で一つの条件しか判定しないときは、後置 if を使うとスッキリする。

```ruby
# 通常のif
if n >= 5
  total += n
end

# 後置if
total += n if n >= 5
```

日本語にすると

「`total += n` する、`n >= 5` の時に」

間違えたポイント

三項演算子は `if` を書く必要がない。

三項演算子は値を返す。

```ruby
# 三項演算子の結果を変数に代入できる
result = 10 > 5 ? "大きい" : "小さい"
p result  # => "大きい"
```

なので、以下のように記述できる。
```ruby
total += a == b ? a * b : a + b
```
