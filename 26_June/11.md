# Git まとめ

## コンフリクトの解消

手順

1. ブランチを最新の状態に
開発ブランチとmainブランチを最新に。

2. マージする
mainブランチを開発ブランチにマージ

3. コンフリクト修正

---

RUNTEQ のデモ

ブランチを最新の状態に

`git branch` で現在のブランチを確認
⇒  * bug_fix
        main

`git switch main` でメインブランチに移動
⇒ bug_fix
     * main

`git pull origin main` でメインブランチを最新に

`git switch bug_fix` でブランチ変更

`git pull origin bug_fix` でbug_fix ブランチを最新に

---

マージする

bug_fix ブランチで `git merge main` で main を bug_fix へマージ

ここでコンフリクトが発生する。
`git status` で確認。

`both modified` と書かれている箇所がコンフリクトしている箇所

---

修正箇所のファイルを開き、どちらの変更を取り込むか選択する。

## ブランチを間違えてしまった場合

`git stash -m "メッセージ"` で変更を隠し場所に避難。

`git status` で変更を確認。何もなくなっている。

変更は stash 上にある（ stash の和訳：隠し場所）
`git stash list` で確認できる。

本来のブランチに移動する。

`git stash list` で stash 上の変更を確認 例 `stash@{0}` 

`git stash pop stash@{0}stash` で stash 上の変更を取り出す。

# JavaScript

## 変数の宣言方法

`let 変数名 = 中に入れる値;` 

let という単語が元になっており、「〜とする」という意味。

`var` は古い変数の指定方法。

そのままの意味で **variable** の略

現在は使われておらず、let を使用する。

ちなみに定数の `const` は constant の略。

## for文の記述例

`for(初回に実行する処理; 繰り返し条件; 各繰り返し後の処理){
繰り返し実行する処理
}`

例

```jsx
for(let i = 1; i <= 10; i++){
  console.log('こんにちは');
}
```

プログラミングの慣習として、ループカウンターの変数名は `i` という変数名にする。

index の略。

`i = i + 1` の省略は `i += 1` もしくは `i ++` 

## insertAdjacentHTML()

HTML に要素を挿入したい場合は `insertAdjacentHTML()` を使う。

```jsx
要素.insertAdjacentHTML('挿入位置', 挿入内容);
```

挿入位置は４つ指定できる。

`beforebegin` 要素の直前に挿入 （和訳：開始前）

`affterbegin` 要素内部の、最初の子要素の前に挿入（和訳：開始後）

`beforeend` 要素内部の、最後の子要素の後に挿入

`afterend` 要素の直後に挿入

## SQL

update で凡ミス。

```jsx
update actors
set first_name = hisaju, last_name = kikumoto
where id = 2;
```

と記述していた。
文字列はシングルクォートで囲む必要がある。

```jsx
UPDATE actors
SET first_name = 'hisaju', last_name = 'kikumoto'
WHERE id = 2;
```
