### Users テーブル

ランキング１位の回数をカウント。

- weekly_ranking_second_count

- badge_type
integer 型、enumでバッジの種類を定義。
- notified_at:
バッジを通知しているか、していないかを判断するカラム。

### User_course_challengesテーブル

- conquered_at
全問正解した日時を記録。
（conquered : 訳 征服した、制覇した）

# 処理の流れ。

トリガーとなるのは `CourseResult` の35行目。

```ruby
course_result.newly_granted_badges = course_result.course_challenge_record || []
```

`.newly_granted_badges` は、9行目の `attr_accessor :newly_granted_badges` でセットしたゲッターとセッター

```ruby
# attr_accessor :newly_granted_badges が生成するもの
def newly_granted_badges        # getter（読み取り）
  @newly_granted_badges
end

def newly_granted_badges=(value) # setter（書き込み）
  @newly_granted_badges = value
end
```

DB には保存されず、`build_from_session!` が終わってコントローラーに `course_result` が返ったあとに、バッジ情報を取り出すために使われる。

---

`course_result.course_challenge_record || []`  で `course_challenge_record` メソッドへ。

## course_challenge_record メソッド

```ruby
  def course_challenge_record
    challenge = UserCourseChallenge.find_or_create_by!(user: user, course: course)

    # 全問正解なら、conquered_at を作成、そうでなければ return する。
    return unless correct_count == total_questions
    UserCourseChallenge.where(id: challenge.id, conquered_at: nil).update_all(conquered_at: Time.current, updated_at: Time.current)

    # バッジ付与チェック
    BadgeGrantService.new(user).grant_course_badges
  end
```

```ruby
challenge = UserCourseChallenge.find_or_create_by!(user: user, course: course)
```

`find_or_create_by!` は「条件に一致するレコードを探して、あればそれを返し、なければ作成して返す」というメソッド。

引数が `(user: user, course: course)` なので、user と course の組み合わせが一致するレコードを探す。
     あれば → そのレコードを返す（2回目以降の挑戦）
     なければ → 作成して返す（初回挑戦）

```ruby
return unless correct_count == total_questions
```

後置 unless 「全問正解しなければ returnする」という意味。

unless は「〜でなければ」
if は「であれば」
で覚えると良い。

```ruby
UserCourseChallenge.where(id: challenge.id, conquered_at: nil).update_all(conquered_at: Time.current, updated_at: Time.current)
```

全問正解したコースの `conquered_at` を更新する。

まず `UserCourseChallenge.where(id: challenge.id, conquered_at: nil)` で conquered_at が nil の UserCourseChallenge を取得。
そして取得したレコードに対して `update_all(conquered_at: Time.current, updated_at: Time.current)` をする。

```ruby
BadgeGrantService.new(user).grant_course_badges
```

BadgeGrantService のインスタンスを作成し、grant_course_badges メソッドを実行。

## BadgeGrantService

grant_course_badges メソッド

```ruby
  def grant_course_badges
    # ユーザーのコースクリア回数
    conquered_count = @user.user_course_challenges.where.not(conquered_at: nil).count

    # 新規取得バッジの空配列を作成
    newly_granted = []

    COURSE_BADGES.each do |badge|
      # .is_a?(Proc) で threshold が Proc (後で実行する処理の塊。ここでは Course.count ) なのか判定。
      # Proc であれば .call で Course.count を実行する。
      threshold = badge[:threshold].is_a?(Proc) ? badge[:threshold].call : badge[:threshold]
      if conquered_count >= threshold
        result = grant_badge(badge[:badge_type], notified: true)
        newly_granted << result if result
      end
    end
    # 戻り値
    newly_granted
  end
```

```ruby
conquered_count = @user.user_course_challenges.where.not(conquered_at: nil).count
```

@userの `user_course_challenges` を取得。
条件は `conquered_at`  が `nil` でないレコード。

`.count` で全問正解したコースの数をカウント。

```ruby
newly_granted = []
```

新規取得のバッジを格納する配列。
このメソッドの戻り値となる。

```ruby
COURSE_BADGES.each do |badge|
```

定数の `COURSE_BADGES` を `each` で一つずつ取り出して処理している。 

```ruby
  COURSE_BADGES = [
    { badge_type: :master,     threshold: -> { Course.count } }, # 全コース。 -> { } で包むことで実行を後まわしにできる( Proc )
    { badge_type: :black_belt, threshold: 15 },
    { badge_type: :brown_belt, threshold: 10 },
    { badge_type: :blue_belt,  threshold: 5 },
    { badge_type: :white_belt, threshold: 1 }
  ].freeze # .freeze で配列の変更を禁止（凍結）
```

```ruby
threshold = badge[:threshold].is_a?(Proc) ? badge[:threshold].call : badge[:threshold]
```

`is_a?` は、そのクラスのインスタンスか？または継承しているか？を確認するメソッド。

ここでの記述は `Proc` クラスのインスタンスかどうかを確認している。

ここでの `Proc` の定義。

```ruby
-> { Course.count }
```

`-> { }` は `Proc.new { }` の省略記法。
ここでは `Course.count` を `Proc` にしており、 `.call` で実行する。

つまり `badge[:threshold].call` で `Course.count` を実行している。

```ruby
if conquered_count >= threshold
```

`conquered_count` が `threshold` よりも大きい場合に以下を実行。

```ruby
result = grant_badge(badge[:badge_type], notified: true) 
```

ここで `grant_badge` メソッドへ。
キーワード引数で `notified: true` を渡している。
この `notified: true` は通知済み（true）、未通知（false）を表している。

## grant_badge メソッド

このメソッドは、新たに取得したバッジのオブジェクトを生成する。

```ruby
  def grant_badge(badge_type, notified: false)
    # ユーザーの badge_type が一致するバッジが DB に存在するなら return する。
    return if @user.user_badges.where(badge_type: badge_type).exists?
    # @user の user_badges レコードを作成。
    @user.user_badges.create!(
      badge_type: badge_type,
      notified_at: notified ? Time.current : nil
      )
  end
```

```ruby
grant_badge(badge_type, notified: false)
```

引数の `notified: false` でデフォルト値を `false` に指定。（つまりデフォルトは未通知）

```ruby
return if @user.user_badges.where(badge_type: badge_type).exists?
```

ユーザーの取得しているバッチを取得。
`.exists?` を使って where 条件に一致するレコードがあるなら true となり、 return する。
レコードがなければ以下の処理を実行してバッジを生成する。

```ruby
@user.user_badges.create!(
      badge_type: badge_type,
      notified_at: notified ? Time.current : nil
      )
```

```ruby
notified_at: notified ? Time.current : nil
```

ここで `true` なら 通知日時を記録。
`false` なら `nil` にする。（未通知）

`grant_course_badges` メソッドへ話を戻す。

---

```ruby
result = grant_badge(badge[:badge_type], notified: true)
```

`result` には新たに作成した `user_badges` のオブジェクトが格納されている。 

すでに取得しているバッジの場合 `nil` が格納される。

```ruby
newly_granted << result if result
```

`result if result` は省略記法。
Rubyでは `nil` と `false` 以外は `true` と評価される。
つまり `result` にオブジェクトが入っていれば `true` となり、 `nil` であれば `false` となる。

```ruby
newly_granted
```

メソッドの戻り値であり、バッジのオブジェクトが入った配列を返している。

呼び出し元の `course_challenge_record` へ戻る。
が、今の処理が最後の行なので、さらに呼び出し元となる

```ruby
course_result.newly_granted_badges = course_result.course_challenge_record || []
```

へ戻る。

`course_result.newly_granted_badges` に取得したバッジの配列が格納される。

`CourseResult.build_from_session!` を呼び出した箇所へ戻る。

`QuizzesController` の `answer` アクション

flash[:new_badges] = course_result.newly_granted_badges.map(&:badge_type)

`badge_icon(badge_type)` は `user_badges_helper` のメソッド。

Rails ではヘルパーに定義したモジュールは全てビューに自動でインクルードされるので使用可能。

```ruby
module UserBadgesHelper
  def badge_icon(badge_type)
    # svg に case文の結果をそのまま代入している。
    svg = case badge_type.to_sym
    when :white_belt     then belt_svg("#f8fafc", "#94a3b8", "#e2e8f0")
    when :blue_belt      then belt_svg("#3b82f6", "#1e3a8a", "#93c5fd")
    when :brown_belt     then belt_svg("#b45309", "#78350f", "#f59e0b")
    when :black_belt     then belt_svg("#1f2937", "#000000", "#4b5563")
    when :master         then master_svg
    when :weekly_king    then crown_svg("#fcd34d", "#b45309", "#ef4444")
    when :weekly_king_3  then crown_svg("#fcd34d", "#b45309", "#3b82f6")
    when :weekly_king_6  then crown_svg("#f9a8d4", "#be185d", "#a855f7")
    when :weekly_king_10 then tenka_muso_svg
    when :weekly_second  then shogi_svg("#f3f4f6", "#6b7280", "#1f2937", "銀将")
    when :weekly_third   then shogi_svg("#fcd34d", "#b45309", "#78350f", "銅将")
    end
    svg&.html_safe
  end
```

`to_sym` は文字列をシンボルに変換するメソッド。

`html_safe` は「この文字列は安全なので HTML としてそのまま出力してよい」と Rails に伝えている。

なぜなら、Rails はセキュリティのため、ビューに出力する文字列を自動でエスケープする
（`<` → `&lt;` など）。XSS（クロスサイトスクリプティング）対策。

```ruby
<%= UserBadge::BADGE_NAMES[badge_type.to_sym] %>
```

`UserBadge::BADGE_NAMES` の記法は、スコープ解決演算子という。
定数を外部から使用するための記述。
https://qiita.com/minisera/items/12b237890a512bb16bac

`UserBadge` クラスの中にある `BADGE_NAMES` 定数」という意味。

`[badge_type.to_sym]` で引数をシンボルにしている。
戻り値は `”白帯"` のような文字列。
