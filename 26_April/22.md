**前回の疑問点について**

- TCP/IPの階層モデルについて
インターネット層とネットワークインターフェース層は逆では？
インターネット層でIPアドレスを扱い、ネットワークインターフェース層でMACアドレスを扱っているのなら逆のように思う。

【AIによる回答】
順番は逆ではありません。
TCP/IPの階層モデルは「抽象度が高い順（物理的な実装から遠い順）」に上から並んでいます。
ネットワークインターフェース層は物理的なケーブルや無線に最も近い層で、同じネットワーク内の隣の機器にデータを届ける役割を持ちます。
MACアドレスは機器に製造時から焼き付けられた識別子で、この「物理的な手渡し」の場面で使われます。
インターネット層はその上に位置し、異なるネットワークをまたいで世界中にデータを届ける役割を持ちます。
IPアドレスはどのネットワークのどの機器に届けるかを示す論理的な住所です。
つまり「どこに届けるか」を決めるインターネット層が上で、「実際に物理的に届ける」ネットワークインターフェース層が下という構造は自然な順番です。
- クッキーとセッションについてもっと理解を深めたい。
クライアント側に保存されるのがクッキーで、クッキーの中身はセッションIDという理解で良いのか？

【AIによる回答】
半分正解ですが、少し補足が必要です。
クッキーはクライアント側に保存されるデータの仕組みそのものです。
クッキーにはセッションIDだけでなく、ユーザーの設定や言語設定など様々な情報を保存できます。
セッションIDを保存する手段としてクッキーが使われることが多いですが、「クッキーの中身＝セッションID」ではありません。
整理すると以下のようになります。
クッキーはブラウザに保存されるデータの入れ物です。有効期限があり、サーバーとブラウザの間でやり取りされます。
セッションはサーバー側に保存されるデータです。ログイン状態やカートの中身など、一連の操作を記憶するために使われます。
セッションIDはそのセッションを識別するための番号で、クッキーに入れてクライアント側に渡されます。
一連の流れはこうなります。
`① ログインする
② サーバーがセッションを作成し、セッションIDを発行
③ セッションIDをクッキーに入れてブラウザに送る
④ 以降のリクエストでブラウザはクッキー（セッションID）を送り続ける
⑤ サーバーはセッションIDでユーザーを特定する`
つまりクッキーはセッションIDの「運び屋」であり、クッキー自体はセッションID以外のものも運べる入れ物です。
- プロトコルに頻出の Transfer(トランスファー）について調べたい。
【AIによる回答】
Transferの意味
「転送する・送り届ける」という意味です。
ネットワーク用語では「データをある場所から別の場所へ運ぶこと」を指します。
プロトコル名での登場例
    
    
    | プロトコル | フルネーム | 用途 |
    | --- | --- | --- |
    | HTTP | HyperText **Transfer** Protocol | Webページの転送 |
    | FTP | File **Transfer** Protocol | ファイルの転送 |
    | SMTP | Simple Mail **Transfer** Protocol | メールの転送 |
    
    ### Protocolとセットで覚える
    
    「**Transfer Protocol**」で「転送規約」という意味になります。
    
    `HTTP = HyperText（Webのテキスト）を
           Transfer（転送する）
           Protocol（ルール・規約）`
    
    「このデータをこのやり方で運びましょう」という取り決めがプロトコルです。
    
    ### まとめ
    
    Transferが入っているプロトコルは「何かをどこかへ届けるためのルール」と覚えると、プロトコル名から用途が推測しやすくなります。
