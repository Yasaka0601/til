## 番号指定パラメータ

```ruby
##### 番号指定パラメーター ######

puts "\n 番号指定パラメーターを使わない場合"
p ['1', '20', '300'].map { |s| s.rjust(3, '0') }

puts "\n 番号指定パラメーターを使う場合"
p ['1', '20', '300'].map { _1.rjust(3, '0') }

dimensions = [
    [10, 20],
    [30, 40],
    [50, 60],
]
dimensions.each { p _1}

puts "\n 入れ子構造になるとエラーになる"
sum = 0
[[1, 2, 3],[4, 5, 6]].each do
    _1.each do
        sum += _1
    end
end

puts "\n エラーにならない"
sum = 0
[[1, 2, 3],[4, 5, 6]].each do |v|
    v.each do
        sum += _1
    end
end
p sum

puts "\n ブロックパラメータと併用するとエラーになる"
['1', '20', '300'].map {|s| _1.rjust(3, '0') }
```

- ブロックパラメータ |n| を使う代わりに _1 から _9 までの数字を使える。
- _1 はそれぞれ「一番目の引数」 _2 「2番目の引数」を表す。
- 入れ子構造の繰り返しに _1 を外側、内側の両方で使用するとエラーとなる。
- ブロックパラメータと併用するとエラーとなる。
- 何を表しているのか分からず可読性が下がるので、短くて分かりやすい処理に使用される。

## ブロックの結合度

do…end と { } はメソッドの結合度が違う。

- { } は結合度が高い
- do…end は結合度が低い

分かりずらいが

```ruby
# 1行の場合は {} を使うのが慣習
[1,2,3].map { |x| x * 2 }

# 複数行の場合は do...end を使うのが慣習
[1,2,3].map do |x|
  x * 2
end
```

という慣習に従っていれば、ほとんどの場合、問題は起きない。

## break と return の違い

- break は 「繰り返し処理から脱出」する
- return は「メソッドから脱出」する

```ruby

def calc_with_break
  numbers = [1, 2, 3, 4, 5, 6]
  target = nil
  numbers.shuffle.each do |n|
    target = n
    # breakで脱出する
    break if n.even?
  end
  target * 10
end
calc_with_break #=> 40

# ----------------------------------------

def calc_with_return
  numbers = [1, 2, 3, 4, 5, 6]
  target = nil
  numbers.shuffle.each do |n|
    target = n
    # returnで脱出する？
    return if n.even?
  end
  target * 10
end
calc_with_return #=> nil
```

## ハッシュについて

each を使用する時、ブロックパラメータを一つにすると配列に格納される。

```ruby

currencies = { 'japan' => 'yen', 'us' => 'dollar', 'india' => 'rupee' }

currencies.each do |n|
    key = n[0]
    value = n[1]
    puts "#{key} : #{value}"
end
```
